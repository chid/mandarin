100% Language-Agnostic Core

The Audio & CTC Engine

  • Audio Processing: 16kHz PCM → 80-dim log-mel filterbank + per-utterance CMVN. Human speech acoustics are universal.
  • 9M Conformer CTC: INT8 quantized ONNX encoder runs entirely client-side via WebAssembly SIMD.
  • Viterbi Trellis Alignment: Dynamic programming alignment operates strictly on frame token probabilities.
  • Blank-Silence Decoupling: Filters frames where P(<blank>) > 0.7 to prevent pauses from penalizing scores.
Language-Specific Adapter Plugs

What Changes Per Language

  • Tokenization Strategy: Syllable+Tone (Tonal languages) vs. Morae (Japanese) vs. Phonemes/GOP (Stress-timed European languages).
  • G2P / Orthography Front-End: Pinyin for Mandarin, Jyutping for Cantonese, Space-syllables for Viet, Trie segmenter for Thai.
  • Phonological Tolerance Rules: Sandhi rules (3-3 tone sandhi), dialectal merges (Hanoi vs Saigon), or liaisons.
  • Training Corpus: ~200–300 hours of paired transcribed speech to train the CTC output layer weights.

🇭🇰 Cantonese (粵語 / Jyutping)

The closest sibling to the Mandarin Ear architecture: closed syllable inventory with 6 distinct tone levels.

Drop-in Rating: 10 / 10
Tonal System
6 Pitch Contours (1–6) + Entering Tones
Vocabulary Size
~1,900 – 2,200 unique tokens
Standard Romanization
LSHK Jyutping (e.g. sik6, faan6)

to-jyutping JS (380 KB bundle)

Cantonese syllable structure is rigorously constrained: Initial Consonant (19 options) + Nucleus Vowel/Diphthong + Coda (Nasal: -m, -n, -ng or Stop: -p, -t, -k) + Tone (1–6). Syllabic nasals (m4, ng5) also exist. Because there are roughly 630 base syllables, the total combinatorial space multiplied across tones is under 2,200 tokens.

Key Differences from Mandarin

  • Entering Tones (入聲): Codas ending in -p, -t, -k are checked (unreleased glottal stops). In Jyutping, they are mapped to tones 7, 8, 9 phonetically, which correspond directly to pitch contours 1, 3, 6 (e.g. sik6 食 is tone 6 contour).
  • Much simpler Sandhi: Cantonese does not have compulsory phonological sandhi like Mandarin's 3-3 sandhi. Tone changes (變音) are mostly morphological (nouns turning into high-rising tone 2, e.g. 糖 tong4 → tong2 candy). The scoring tolerance only needs to permit alternative dictionary readings.

Front-End JS Implementation

// In-browser Cantonese conversion using to-jyutping import { getJyutpingList } from 'to-jyutping'; function sentenceToTokens(cantoneseText) { const raw = getJyutpingList(cantoneseText); // Output: [['食', 'sik6'], ['咗', 'zo2'], ['飯', 'faan6'], ['未', 'mei6']] return raw.map(([char, jp]) => ({ char, token: jp.toLowerCase() // e.g. "sik6" })); }

🇻🇳 Vietnamese (Tiếng Việt / Quốc ngữ)

The easiest front-end implementation: words are already written with space-separated syllables.

Drop-in Rating: 10 / 10

Vocabulary Size

In written Vietnamese, every single syllable is space-delimited by orthographic design (e.g. "Cộng hòa xã hội chủ nghĩa Việt Nam"). This completely eliminates the need for complex G2P neural networks, Hanzi pinyin dictionaries, or segmentation engines. Every space-delimited word is a direct syllable token.

Acoustic Considerations for CTC

  • Creaky Voice & Glottalization: Vietnamese tones are defined not just by pitch (F0), but by phonation register. Tones ngã and nặng involve vocal fold tension and glottal closures. The 80-dim log-mel spectrogram captures these spectral irregularities effortlessly, giving the Conformer high discriminant power.
  • Regional Dialects (Northern vs Southern): In Southern Vietnamese (Saigon), the hỏi and ngã tones merge into a single tone contour (~323). The scoring engine can provide a toggle: strictNorthern: true/false to accept merged confidence.

Front-End Tokenizer

// Vietnamese Syllable Extraction (Zero heavy dependencies required) function vietnameseToTokens(sentence) { // Normalize Unicode NFC (ensure composite diacritics match vocab) const clean = sentence.normalize('NFC').toLowerCase(); const words = clean.trim().split(/\s+/); return words.map(w => ({ ortho: w, token: w // directly matches vocab.json entry! })); }

🇹🇭 Thai (ภาษาไทย)

5 phonemic tones with consonant classes and vowel length duration distinctions.

Drop-in Rating: 8.5 / 10
Tonal System
5 Lexical Tones (Mid, Low, Falling, High, Rising)

~3,000 – 4,000 syllable+tone combinations
Vowel Length
Phonemic (Short vs Long vowels change word meaning)

Script has no spaces; requires syllable tokenizer

Thai orthography is an abugida where syllables are written continuously without spaces (spaces are used like commas or periods). Thai tones are computed through a four-way matrix: Consonant Class (Low, Mid, High) × Vowel Length (Short vs Long) × Syllable Ending (Live vs Dead / Sonorant vs Stop) × Tone Diacritic (่ , ้ , ๊ , ๋).

Key Technical Nuances for Thai CTC

  • Syllable Segmentation: Because Thai lacks word spaces, sentences like สวัสดีครับ must be split into syllables: สะ-หวัด-ดี-ครับ (sa-wat-dee-khrap). In Python, pythainlp.tokenize.syllable_tokenize handles this with >98% accuracy. In JavaScript, a compact 150KB Trie dictionary or regex maximal-matching rule segments syllables client-side.
  • Vowel Duration Modeling: Short vs Long vowels are phonemic (e.g. khao [rice] vs khaao [news]). Because the CTC Conformer frames are 40ms, a short vowel typically spans 2–3 frames while a long vowel spans 5–8 frames. The Viterbi trellis automatically learns duration constraints via repeat tokens.

Thai Syllable Tokenization Pipeline

# Python G2P Pipeline using PyThaiNLP from pythainlp.tokenize import syllable_tokenize from pythainlp.transliterate import romanize def thai_to_tokens(text: str): syllables = syllable_tokenize(text) # syllables: ['สะ', 'หวัด', 'ดี', 'ครับ'] tokens = [romanize(s, engine="royin") for s in syllables] return tokens # ['sa', 'wat', 'di', 'khrap']

Implementation Guide

Step-by-Step Model Porting Blueprint

From raw speech corpus to optimized on-device WebAssembly binary.

Step 1: Dataset & Vocabulary

Build vocab.json

Download ~200–300 hours of speech from Common Voice or AISHELL. Extract all unique syllable+tone pairs across the transcripts.

vocab = ["<blank>", "<unk>"] + sorted(all_unique_tokens) with open("vocab.json", "w") as f: json.dump(vocab, f, ensure_ascii=False)
Step 2: Conformer CTC Training

Train 9M Conformer

4 Conformer encoder layers, 256 d_model, 4 attention heads, depthwise conv kernel 31. Total ~9.2M parameters.

# 8 hours on 4x RTX 4090 loss = nn.CTCLoss(blank=0, zero_infinity=True) optimizer = AdamW(model.parameters(), lr=1e-3)
Step 3: ONNX & INT8 Quantization

Export & Compress

Export FP32 ONNX graph (~37 MB) and apply dynamic INT8 quantization to achieve ~11–13 MB with zero perceptual degradation.

from onnxruntime.quantization import quantize_dynamic quantize_dynamic("model.onnx", "model_int8.onnx", weight_type=QuantType.QInt8)
Step 4: Web Deployment

Plug into index.html

Drop the quantized .onnx and new vocab.json into the folder. Switch front-end romanization script.

const session = await ort.InferenceSession .create('./tiny_int8.onnx', { executionProviders: ['wasm'] });
